# CLAUDE.md — 수원시보건소 모바일 웹 개편

이 프로젝트에서 작업할 때 따를 규칙입니다. 서비스 요구사항의 원본은 `docs/prd.md`이며, 이 파일과 PRD 내용이 다르면 PRD를 따르고 사용자에게 알립니다. 단, 화면 문구·배치는 Figma 완성본이 우선이며(사용자 결정), 이미 정한 차이는 아래 「Figma와 다르게 구현하는 부분」과 PRD 6장의 「구현:」 줄에 있습니다.

## 1. 사용자
- 이 서비스는 **코딩 초보자**가 만듭니다.
  - 설명은 쉬운 말로 하고, 전문 용어를 쓰면 짧게 풀어 줍니다.
  - 무엇을 왜 바꿨는지, 결과를 어떻게 확인하는지 함께 알려 줍니다.
  - 한 번에 많은 것을 바꾸지 말고, 작은 단위로 나눠 진행합니다.
- **모르거나 애매한 부분은 추측하지 말고 사용자에게 질문합니다.**
  - PRD나 Figma에 없는 문구, 색상, 크기, 동작
  - 해석이 두 가지 이상 가능한 요청
  - 파일 삭제, 구조 변경처럼 되돌리기 어려운 작업
- 모든 답변과 설명은 한국어로 합니다.

## 2. 기술 스택 (변경 금지)
프로젝트 초기화 때 정한 스택입니다. **사용자가 직접 요청하기 전에는 바꾸거나 다른 기술을 추가하지 않습니다.**

## 3. 디자인 규칙
- **디자인은 추후 Figma MCP로 구현합니다.** 사용자가 Figma 링크를 주기 전에는 화면 디자인(색, 간격, 배치)을 임의로 만들지 않습니다.
  - Figma 파일: https://www.figma.com/design/ttUW1a9zYIsPGMGH3VCiBz/
  - 모바일 화면: 「3-4. 완성형화면」 페이지의 「모바일형」 섹션 (node 2262:7109)
  - 데스크톱 화면: 같은 페이지의 「데스크탑반응형」 섹션
  - 개발 핸드오프: 「핸드오프 문서」 페이지 (node 3446:1159)
- **Figma 프레임과 페이지 대응**: 모바일 프레임은 7개지만 실제 페이지는 4개입니다. 모바일 3~6은 통합민원 한 페이지에서 아코디언 펼침 상태만 다른 화면입니다.

| Figma 프레임 | 페이지 | 상태 |
|---|---|---|
| 모바일 1 | 화면 1 메인 | – |
| 모바일 2 | 화면 2 구 보건소 (팔달 기준, 4개 구 공용) | – |
| 모바일 3 | 화면 3 통합민원 | 제증명발급 펼침 |
| 모바일 4 | 화면 3 통합민원 | 예방접종 펼침 |
| 모바일 5 | 화면 3 통합민원 | 진료및검사 펼침 |
| 모바일 6 | 화면 3 통합민원 | 금연서비스 펼침 |
| 모바일 7 | 화면 4 위치·교통 | – |
- **디자인 토큰**: Figma '개선디자인토큰' 컬렉션만 씁니다. '원시토큰' 컬렉션 값은 쓰지 않습니다.
  - 이름 규칙: Figma 변수명의 `/`와 공백을 `-`로 바꿉니다 (`color/blue/700` → `--color-blue-700`, `text/line height/24` → `--text-line-height-24`).
  - 색상·크기를 직접 적지 말고 `tokens.css` 변수를 씁니다. 토큰에 없는 값이 필요하면 먼저 사용자에게 묻습니다.
  - Figma 변수에 없어 `tokens.css`에 따로 추가한 토큰:
    - 그림자: `--shadow-floating`(탑버튼), `--shadow-bottom-bar`(하단 고정 긴급원클릭서비스)
    - 간격: `--space-4` · `8` · `12` · `16` · `20` · `24` · `32` · `36` · `64`
    - 원형 라운드: `--radius-full`(50%)
    - 접근성: `--touch-target-min`(44px), `--focus-ring`, `--focus-ring-offset`
  - 텍스트 스타일 변수 `--typo-*`는 `font: var(--typo-body);`처럼 한 줄로 씁니다.
  - 검색창 플레이스홀더는 Figma의 #767676 대신 `--color-grey-400`을 씁니다(토큰에 없는 색이고, 대비가 4.54로 기준에 겨우 맞아 바꿈).
- **텍스트 스타일**: `base.css` 클래스를 씁니다. `.text-title`(대제목), `.text-section`(섹션타이틀), `.text-card`(카드및버튼타이틀), `.text-body`(본문), `.text-caption`(캡션및보조설명)
- **폰트**: Pretendard GOV (`--font-family`). `src/fonts`의 woff2 4개(400, 500, 600, 700)를 `src/styles/fonts.css`에서 등록합니다. 다른 굵기가 필요하면 파일 추가 전에 먼저 묻습니다.
- **단위**: 레이아웃은 Flexbox/Grid와 상대 단위(rem, %)로 구성하고, 고정 px 너비는 쓰지 않습니다. 1rem = 16px입니다.
- **반응형** (PRD 11장)

| 구분 | 범위 | Figma 기준 프레임 | 레이아웃 |
|---|---|---|---|
| 모바일 | 360px ~ 840px (기본) | 360 × 840 | 좌우 여백 16px, 섹션 간격 36px |
| 데스크톱 | 841px 이상 | 1440 × 1024 | 콘텐츠 최대 1200px 가운데 정렬, 섹션 간격 64px |

  - 모바일 우선으로 작성하고 미디어쿼리는 `min-width`만 씁니다. 데스크톱은 `@media (min-width: 52.5625em)`(841px)입니다.
  - 사이즈별 상세 반응형 디자인은 Figma 링크를 받은 뒤 구현합니다 (5. 안전 규칙 참고).
- **문구**: 화면 문구는 Figma 완성본 문구를 그대로 옮기고, 확실한 오타만 고칩니다 (사용자 결정 — PRD 문구와 다르면 Figma 우선, PRD 6장에 「구현:」으로 기록).
- **접근성**: KRDS 2025.08, KWCAG 2.2를 지킵니다.
  - 한 손 조작을 고려해 터치 영역을 충분히 확보합니다.
  - 아이콘만 있는 버튼에는 `aria-label`, 아코디언은 `button` + `aria-expanded`, 탭은 `role="tablist"`를 씁니다.

## 5. 안전 규칙
- **Claude는 정보와 선택지만 제공하고, 결정과 실행 여부는 사용자가 정합니다.** 파일 수정, Figma 수정, 명령어 실행 등 모든 작업은 먼저 묻고 승인받은 뒤 진행합니다.
- **기술 스택은 바꾸지 않습니다.** 프레임워크, 언어, 스타일 방식을 바꾸거나 TypeScript·CSS 프레임워크를 도입하지 않습니다.
- **패키지 설치(`npm install`) 전에 이유를 설명하고 허락받습니다.** 무엇을 왜 설치하는지 설명하고, 허락을 받기 전에는 설치하지 않습니다. 패키지 삭제도 같습니다.
- **파일 삭제, 이름 변경, 폴더 구조 변경 전에는 반드시 먼저 물어봅니다.** 허락을 받기 전에는 실행하지 않습니다.
- **`docs/prd.md`는 사용자가 요청할 때만 수정합니다.**
- **한 번에 여러 화면을 수정하지 않고, 요청한 범위만 작업합니다.** 관련 없는 코드나 스타일을 정리하고 싶으면 따로 제안합니다.
- **에러가 나면 임의로 우회하지 말고 원인을 먼저 설명합니다.** 에러를 숨기거나, 코드를 지우거나, 검사를 끄는 식으로 넘어가지 않습니다. 원인과 해결 방법을 설명한 뒤 진행합니다.
- **색상, 폰트, 간격, 라운드, 그림자는 `src/styles/tokens.css`의 변수만 사용합니다 (하드코딩 금지).** 필요한 값이 `tokens.css`에 없으면 직접 적지 말고 먼저 사용자에게 묻습니다.
- **새 값이 필요하면 임의로 만들지 말고 먼저 물어봅니다.** 색상, 크기, 문구, 아이콘, 동작 모두 해당합니다.
- **컴포넌트는 `src/components/` 아래 종류별 폴더(`button`, `card`, `form`, `section`)에 컴포넌트마다 폴더 하나로 만듭니다.** 폴더 이름과 파일 이름은 컴포넌트 이름과 같게 합니다(예: `src/components/button/MenuButton/MenuButton.jsx`, `MenuButton.css`).
- **반응형은 `docs/prd.md`의 브레이크포인트 기준(11장)을 따르며, 사이즈별 Figma 링크를 받은 뒤에 구현합니다.** 링크를 받기 전에는 데스크톱 배치를 임의로 만들지 않습니다.
- **구현 후에는 반드시 Figma와 비교해서 다른 부분을 보고합니다.** 구현한 화면과 Figma를 비교하고, 다른 부분(크기, 간격, 색, 문구, 배치)을 목록으로 알려 줍니다. 차이가 없으면 없다고 알립니다.
- **Figma에서 읽지 못한 정보는 추측하지 말고 질문합니다.** 값이 비어 있거나, 화면마다 다르거나, 의도를 알 수 없으면 구현 전에 묻습니다.
- **접근성이 깨지지 않게 구현합니다.**
  - 버튼, 카드, 네비게이션 높이는 `height` 대신 `min-height`로 지정합니다. 글자를 키워도 잘리지 않아야 합니다.
  - 320px 폭에서도 가로 스크롤이 생기지 않아야 합니다. 한 줄에 여러 개 놓이는 구 버튼 4개는 좁은 화면에서 줄바꿈되게 합니다. 단, 공지 지역 버튼 5개는 사용자 결정으로 항상 한 줄입니다.
  - 눌리는 요소는 `--touch-target-min`(44px) 이상으로 만듭니다. 아이콘이 24px이어도 눌리는 영역은 44px입니다.
  - 선택 상태는 색만으로 구분하지 않고 굵기·테두리를 함께 바꾸며, `aria-selected`나 `aria-pressed`를 넣습니다.
  - 테두리 없이 배경색(blue/50, blue/100)만으로 카드를 구분하지 않습니다. 흰 배경과 대비가 1.1로 낮습니다.
  - `--color-grey-100`은 장식용 구분선에만 쓰고, 버튼·입력창 테두리로 쓰지 않습니다(흰 배경 대비 1.52).
  - 포커스 표시(`:focus-visible`)와 움직임 줄이기(`prefers-reduced-motion`)는 `base.css`에 전역으로 들어 있으니 지우거나 덮어쓰지 않습니다.
- **Git**: 커밋과 푸시는 사용자가 요청할 때만 합니다. `push --force`, `reset --hard` 같은 되돌리기 어려운 명령은 쓰지 않습니다.
- **외부 연결**: 전화번호, 외부 사이트 링크는 PRD에 적힌 대상만 연결합니다. 실제 개인정보나 비밀 키를 코드에 넣지 않습니다.
- **Figma 파일**: Figma MCP로 원본 디자인 화면을 수정하거나 지우지 않습니다. 읽기만 하고, 쓰기가 필요하면 먼저 묻습니다.
- **작업 후 확인**: 코드를 바꾸면 `npm run build`와 `npm run lint`를 실행해 통과하는지 확인하고, 결과를 그대로 보고합니다. 실패하면 숨기지 말고 알립니다.
