# 수원시 보건소 모바일 웹 개선 프로젝트

> 수원시 보건소 모바일 웹에 내 지역 버튼을 도입해 헛걸음을 줄인 개선안<br>
> 서비스 카드를 재배치해, 필요한 서비스를 주소지 보건소에서만 신청할 수 있는지, 가까운 보건소에서도 신청할 수 있는지 한눈에 알 수 있도록 함<br>
> 관할·통합·긴급 정보를 나눠 배치해 필요한 정보를 찾는 시간을 줄임

## 2. 프로젝트 정보

- **제작 기간**: 2026.11.06 ~ 2026.11.09 (4일)
- **담당 역할**: 개인 프로젝트 (기여도 100%)
- **담당 범위**: Figma 개선 디자인 → 바이브코딩 구현 → GitHub Pages 배포

## 3. 사용 기술

- **React, Vite**: 화면을 컴포넌트로 나눠 수정하기 쉽게 구현하고, 배포할 파일을 만드는 데 사용
- **GitHub Pages**: 무료 배포
- **Figma**: 개선 디자인
- **Claude**: 바이브코딩 (화면 구현)

## 4. 주요 기능

- **기능 1. 내 지역 버튼**: 첫 화면에서 주소지 보건소에서만 신청할 수 있는 서비스를 안내하고, 구 버튼을 누르면 관할구에 따른 의료비지원 메뉴 11개와 자격·지원 내용을 볼 수 있음
- **기능 2. 통합민원서비스**: 주소지와 상관없이 이용할 수 있는 서비스 카드를 누르면 해당 내용이 펼쳐진 화면으로 이동함
- **기능 3. 긴급원클릭서비스**: 급할 때 쓰는 서비스인 휴일지킴이, 자동심장충격기 찾기, 달빛어린이병원을 모바일에서는 화면 하단에 고정하고, 데스크톱에서는 페이지 끝에 펼쳐 둠

## 5. 트러블슈팅

### 이슈 1: 서비스 카드 재분류의 어려움

- **문제**: 서비스를 어떤 기준으로 분류하고 묶어야 할지 명확하지 않아 정보 구조를 설계하는 데 어려움이 있었음
- **원인**: 기존 사이트에 서비스별 카테고리나 분류 기준이 없이 서비스가 단순 나열식으로 구성되어 있었음
- **해결**: 다른 보건소 사이트의 분류 체계를 분석하고, 네이버 지식iN에서 자주 묻는 질문과 답변을 참고해 서비스를 재분류함

### 이슈 2: 배포 후 새로고침하면 404 오류 발생

- **문제**: 배포한 사이트의 메인이 아닌 화면에서 새로고침하거나 주소를 직접 입력하면 404 페이지가 나왔음
- **원인**: GitHub Pages는 실제 파일이 있는 주소만 보여 주는데, 이 사이트는 파일 하나로 모든 화면을 보여 주는 방식이라 메인이 아닌 화면의 주소에는 파일이 없었음
- **해결**: 404 페이지 대신에도 같은 파일(index.html)이 열리도록 복사해 두어, 어느 화면에서 새로고침해도 원래 보던 화면이 나오도록 함

## 6. AI 활용 방식

- **맡긴 일**: Figma 화면을 React 컴포넌트로 구현, GitHub Pages 배포 오류 해결
- **핵심 프롬프트**: "이 프레임을 모바일 너비(360px~), 데스크톱(1440px~) 기준으로 구현해 줘", "새로고침하면 404가 나와. 해결 방법 알려 줘"

## 7. 회고

- **배운 점**
  - 이용자들이 자주 묻는 질문을 분석하면 분류 기준을 찾을 수 있고, 이용자 입장에서 정보를 정리해야 한다는 점을 배웠음
  - 개발 환경에서 잘 동작해도 배포 환경에서는 다르게 동작할 수 있어, 배포한 뒤에도 실제 주소로 직접 확인하는 과정이 필요하다는 것을 알게 되었음
- **아쉬운 점**
  - 다른 보건소 사이트에서 확인할 수 없는 정보는 정확한지 검증하기 어려웠음
  - 배포 환경이 개발 환경과 어떻게 다른지 미리 알아보지 않아, 배포한 뒤에야 새로고침 404 오류를 발견했음
