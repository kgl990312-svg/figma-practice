# 수원시 보건소 앱 개선 프로젝트

> 수원시 보건소 앱에 내 지역 버튼을 도입해 헛걸음을 줄인 개선안<br>
> 보건 주요 서비스 카드를 재배치해, 필요한 서비스를 주소지 보건소에서만 신청할 수 있는지, 가까운 보건소에서도 신청할 수 있는지 한눈에 알 수 있도록 함<br>
> 관할·통합·긴급 정보를 나눠 배치해 필요한 정보를 찾는 시간을 줄임

- **제작 기간**: 2026.11.06 ~ 2026.11.09 (4일)

## 3. 사용 기술

- **React, Vite**: 화면을 컴포넌트로 나눠 수정하기 쉽게 구현,개발 서버 실행과 배포용 빌드
- **GitHub Pages**: 무료 배포
- **Figma**: 개선 디자인
- **Claude**: 바이브코딩 (화면 구현)

## 4. 주요 기능

- **기능 1. 서비스 카드 재배치와 내 지역 버튼**: 서비스 카드를 보건 주요 서비스, 통합민원서비스, 긴급원클릭서비스의 세 영역으로 나눠, 원하는 서비스가 어떤 종류인지 알고 알맞은 경로를 고를 수 있음. 첫 화면의 안내문과 내 지역 버튼으로 관할 보건사업을 헛걸음 없이 찾을 수 있음
- **기능 2. 의료비지원·위치·공지 안내**: 의료비지원 메뉴 11개를 누르면 해당 지원사업의 자격과 지원 내용을 바로 확인할 수 있음. 구별 보건소의 주소, 지도, 운영·휴게시간, 대중교통·주차 정보를 한 화면에서 보고, 공통·팔달·권선·장안·영통 버튼으로 지역별 최근 공지도 골라 볼 수 있음
- **기능 3. 긴급원클릭서비스 하단 고정과 반응형 레이아웃**: 휴일지킴이, 자동심장충격기 찾기, 달빛어린이병원을 화면 하단에 고정해 휴일·야간에도 바로 찾을 수 있음. 모바일과 데스크톱 모두에서 같은 기능을 편하게 쓸 수 있도록 반응형으로 구현함

## 5. 트러블슈팅

### 이슈 1: 서비스 카드 재분류의 어려움

- **문제**: 서비스를 어떤 기준으로 분류하고 묶어야 할지 명확하지 않아 정보 구조를 설계하는 데 어려움이 있었음
- **원인**: 기존 사이트에 서비스별 카테고리나 분류 기준이 없이 서비스가 단순 나열식으로 구성되어 있었음
- **해결**: 다른 보건소 사이트의 분류 체계를 분석하고, 네이버 지식iN에서 자주 묻는 질문과 답변을 참고해 서비스를 재분류함

### 이슈 2: 배포 후 하위 페이지에서 새로고침하면 404 오류

- **문제**: GitHub Pages에서 같은 주소를 새로고침하거나 직접 열면 404 페이지가 나왔음
- **원인**: GitHub Pages는 실제 파일이 있는 주소만 보여 주는데, 화면은 React가 주소를 보고 고르는 방식이라 해당 파일이 없었음
- **해결**: 빌드할 때 index.html을 404.html로 복사해, 없는 주소로 들어와도 앱이 열린 뒤 주소에 맞는 화면을 보여 주도록 함

## 6. AI 활용 방식

- **맡긴 일**: Figma 화면을 React 컴포넌트로 구현, GitHub Pages 배포 오류 해결
- **핵심 프롬프트**: "이 프레임을 모바일 너비(360px~), 데스크톱(1440px~) 기준으로 구현해 줘", "새로고침하면 404가 나와 해결방법 알려줘"
## 7. 회고

- **배운 점**
  - 실제 이용자들이 자주 묻는 질문을 분석하면 분류 기준을 찾을 수 있고, 이용자 관점에서 정보를 구성하는 것이 중요하다는 것을 배웠음
  - 개발 환경에서 잘 동작해도 배포 환경에서는 다르게 동작할 수 있어, 배포한 뒤에도 실제 주소로 직접 확인하는 과정이 필요하다는 것을 알게 되었음
- **아쉬운 점**
  - 다른 보건소 사이트에서 확인할 수 없는 정보는 정확한지 검증하기 어려웠음
  - 초기 설계 단계에서 컴포넌트의 구조와 활용 범위를 충분히 정하지 못해 불필요하게 복잡한 형태로 만든 점이 아쉬움
